# lab10. Функциональные зависимости и нормализация купонов

Вариант 4: `coupon_flat(coupon_code, valid_from, valid_to, category_name, customer_id, customer_city, use_date, discount)`.

Обозначим C — coupon_code, U — customer_id, D — use_date, G — category_name. Одно использование идентифицируется тройкой (C,U,D), как задано условием. Поэтому в плоском отношении одна такая тройка имеет одну категорию G. Если купон применим к нескольким категориям, это отдельное отношение применимости из №8; нельзя независимо соединять все категории купона со всеми использованиями, поскольку появятся ложные строки.

## Зависимости и ключ

Минимальное покрытие (правые части разделяются на одиночные атрибуты):

* C → valid_from, valid_to, discount.
* U → customer_city.
* (C,U,D) → G — следствие правила идентификации одного использования.

`{C,U,D}+` сначала содержит C,U,D; по первой зависимости добавляются срок и скидка, по второй — город, по третьей — категория. Получены все восемь атрибутов, значит K=(C,U,D) — суперключ. Он минимален: C, U и D не стоят справа нетривиальных ФЗ и не могут быть выведены из оставшихся атрибутов. Это единственный кандидатный ключ при перечисленных правилах.

Зависимости C → срок,скидка и U → город частичные: детерминант — собственное подмножество K. Дополнительной транзитивной зависимости через неключевой атрибут условие не задаёт; category_name не определяет другие атрибуты. Не следует выводить новые бизнес-ФЗ только из совпадений небольшого тестового набора.

## Аномалии

* INSERT: новый купон нельзя сохранить без искусственного использования и клиента.
* UPDATE: изменение скидки купона требует менять каждую строку его использования; пропуск строки создаёт противоречие.
* DELETE: удаление последнего использования купона уничтожает сведения о сроках и скидке; последнее использование клиента уничтожает его город.

## Последовательная декомпозиция

1. 1НФ: атрибуты атомарны, одно использование — одна строка, повторяющихся групп нет.
2. По C → valid_from,valid_to,discount выделяется **Coupons(C, valid_from, valid_to, discount)**; остаток — (C,U,D,G,customer_city). Пересечение {C} — ключ Coupons, поэтому соединение без потерь.
3. По U → customer_city выделяется **Customers(U, customer_city)**; остаток — **Uses(C,U,D,G)**. Пересечение {U} — ключ Customers, снова соединение без потерь. Частичные зависимости устранены: получена 2НФ.
4. Транзитивных нарушений нет: эти отношения уже в 3НФ. Каждый нетривиальный детерминант является ключом своего отношения, поэтому достигнута также **НФБК**.

Все исходные ФЗ сохранены внутри одного из отношений. Последовательность двух разбиений без потерь доказывает отсутствие потерь для итоговой декомпозиции. Первичные ключи реализуют ФЗ; Uses имеет FK к справочникам. nf_4_customers ссылается на реальных клиентов Olist; город хранится здесь только как учебная демонстрация заданной ФЗ.

Тест: **3 определения купонов, 3 клиента и 5 использований**. Обратный JOIN даёт 5 строк плоского отношения. Скидка NF4_A (5%) и город первого клиента хранятся один раз, хотя встречаются в нескольких восстановленных строках. PRIMARY KEY уже гарантирует UNIQUE ключевых наборов; дополнительный повторяющий его UNIQUE не нужен.

## Контрольные вопросы

1. Замыкание X+ — все атрибуты, выводимые из X последовательным применением ФЗ.
2. 3НФ допускает неключевой детерминант, если зависимый атрибут является простым (входит в кандидатный ключ); НФБК требует суперключ для каждого нетривиального детерминанта.
3. Декомпозиция без потерь означает, что JOIN проекций восстанавливает исходное отношение без ложных кортежей.
