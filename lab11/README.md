# lab11. Представления и рекурсивные CTE

Вариант 4: корень PR. `v_order_summary` содержит одну строку на каждый заказ, в том числе без позиций: LEFT JOIN с предварительно агрегированными позициями даёт item_count=0 и total=0. Сумма — price+freight_value. `mv_monthly_state_sales` агрегирует доставленные заказы по месяцу покупки и штату; REFRESH пересчитывает содержимое.

Иерархия: **BR → ST:штат → CT:штат:город**. В каждом штате взяты не более 20 самых крупных по числу строк customers городов; при равном числе применяется сортировка по имени. Одинаковые названия в разных штатах имеют разные node_id.

Пример пути: `ST:PR -> CT:PR:curitiba`. Базовая часть прямой рекурсии выбирает ST:PR с depth=0; рекурсивная добавляет детей с depth+1. Обратный запрос начинает с минимального city-node PR и идёт через parent_id до BR. Подсчёт потомков начинается от каждого штата; сам корень вычитается из COUNT.

Проверка цикла выполняется только во временной копии. Массив path хранит посещённые node_id; `NOT next.node_id = ANY(path)` не допускает повторного посещения и гарантирует завершение на конечном графе.

## Контрольные вопросы

1. VIEW хранит определение запроса, MATERIALIZED VIEW — вычисленные строки. Материализованное представление может устареть и требует REFRESH.
2. Рекурсия завершается, когда рекурсивная часть не добавляет строк; на циклах необходима защита path или SQL CYCLE.
3. Повторение отношения parent→child вычисляет достижимость по пути произвольной длины, то есть транзитивное замыкание.

## Запуск и состав

Подключение: `psql -h localhost -p 5433 -U student -d olist`. Схема olist должна быть загружена по №1. Запуск из этой папки: `psql -h localhost -p 5433 -U student -d olist -v ON_ERROR_STOP=1 -f lab11.sql`. Каждый файл запускайте в отдельном сеансе: временные таблицы принадлежат сеансу. ФИО и группу впишите в шапку SQL. `results.txt` содержит фактический вывод на ваших CSV.
