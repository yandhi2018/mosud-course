# lab05. Кванторы и реляционное деление

Вариант 4: `S = {GO, DF, MT}`. Рассматриваются только доставленные заказы и известные категории. Универсальное множество — все 73 непустые категории `olist.products`.

Двойной `NOT EXISTS`, `GROUP BY/HAVING` и `EXCEPT` находят **48 категорий**. Все четыре направленные EXCEPT-проверки дали 0 различий. Для категории `alimentos`: DF — 7 заказов, GO — 6, MT — 6. Дополнительный запрос находит продавцов с продажами во всех трёх штатах.

При пустом S все три реализации возвращают **73 категории**: не существует обязательного штата, нарушающего условие. В COUNT-решении LEFT JOIN начинается с универсального множества; простой INNER JOIN с пустым S ошибочно дал бы пустой результат.

## Контрольные вопросы

1. `∀x P(x)` эквивалентно `¬∃x ¬P(x)`. Здесь нарушение — обязательный штат без продажи категории.
2. Считаются различные покрытые штаты из S; равенство мощности S означает полное покрытие. Без DISTINCT многократные продажи завысили бы счётчик.
3. На пустом множестве универсальное условие истинно для каждого кандидата: это вакуумная истинность.

## Запуск и состав

Подключение: `psql -h localhost -p 5433 -U student -d olist`. Схема olist должна быть загружена по №1. Запуск из этой папки: `psql -h localhost -p 5433 -U student -d olist -v ON_ERROR_STOP=1 -f lab05.sql`. Каждый файл запускайте в отдельном сеансе: временные таблицы принадлежат сеансу. ФИО и группу впишите в шапку SQL. `results.txt` содержит фактический вывод на ваших CSV.
