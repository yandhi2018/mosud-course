# lab14. EXPLAIN ANALYZE и переписывание антисоединения

Вариант 4: заказы без отзывов. Исходная форма использует NOT IN, новая — коррелированный NOT EXISTS. В Olist order_id обеих таблиц NOT NULL, поэтому формы эквивалентны: **768 заказов**, EXCEPT в обе стороны — 0 строк.

| Форма | Узел | estimated rows | actual rows | actual total, мс | Execution, мс | shared hit / read |
|---|---|---:|---:|---:|---:|---:|
| NOT IN | Seq Scan | 49720 | 768 | 38.455 | 38.491 | 3640 / 0 |
| NOT EXISTS | Hash Join (Anti) | 1102 | 768 | 36.462 | 36.523 | 3640 / 0 |

Наиболее дорогой узел исходного плана по inclusive actual total time — Seq Scan: 38.455 мс; нового — Hash Join: 36.462 мс. Время родителя включает работу потомков; нельзя складывать времена всех узлов как независимые затраты. estimated/actual rows ключевого узла приведены в таблице.


NOT IN использует hashed SubPlan, NOT EXISTS — Hash Anti Join. В обоих случаях отзывы читаются один раз и строится хеш, поэтому **само переписывание не гарантирует ускорения**; оцениваются приведённые фактические времена и buffers. Антисоединение устраняет ненужное размножение строк и позволяет оптимизатору явно выбрать алгоритм отсутствия связи. Алгебра: `orders − π_orders(orders ⋈ reviews)`. Промежуточные объёмы и оценки всех узлов сохранены в plans.json.

При добавлении NULL в временное множество review ids NOT IN вернул **0**, NOT EXISTS — **768**. Равенство двух форм относится к исходной схеме с NOT NULL; переписывать их как безусловно эквивалентные при допустимых NULL нельзя.

Условия замера те же, что в №13: PostgreSQL 17, один worker, прогретый кэш. Дополнительные индексы не понадобились; исходные строки Olist сохранены.

## Контрольные вопросы

1. Меньше промежуточных строк означает меньше построений/проверок хеша, сортировок, передач данных и работы последующих операторов.
2. Расхождение estimated и actual rows показывает ошибку оценки селективности/кратности и может привести к неудачному порядку или алгоритму JOIN; проверяют статистику и зависимости условий.
3. Быстрый запрос с другим результатом не является оптимизацией исходного: двусторонний EXCEPT проверяет равенство множеств; если важны дубликаты, нужен EXCEPT ALL.

## Запуск и состав

Подключение: `psql -h localhost -p 5433 -U student -d olist`. Схема olist должна быть загружена по №1. Запуск из этой папки: `psql -h localhost -p 5433 -U student -d olist -v ON_ERROR_STOP=1 -f lab14.sql`. Каждый файл запускайте в отдельном сеансе: временные таблицы принадлежат сеансу. ФИО и группу впишите в шапку SQL. `results.txt` содержит фактический вывод на ваших CSV.
