# lab13. Индексы и физический доступ

Вариант 4: низкая оценка за период. Первый запрос — review_score=1, даты [2018-01-01, 2018-02-01). Составной B-tree ставит равенство score первым и диапазон date вторым. Второй индекс — частичный по дате для review_score≤2, запрос явно включает его предикат.

## Фактические планы PostgreSQL 17

| Форма | Узел | estimated rows | actual rows | actual total, мс | Execution, мс | shared hit / read |
|---|---|---:|---:|---:|---:|---:|
| До индекса, score=1 | Seq Scan | 715 | 707 | 6.512 | 6.539 | 1800 / 0 |
| Составной, score=1 | Bitmap Heap Scan | 723 | 707 | 0.586 | 0.615 | 590 / 2 |
| Низкая селективность, score≥1 | Seq Scan | 99224 | 99224 | 5.664 | 7.761 | 1800 / 0 |
| Частичный, score≤2 | Bitmap Heap Scan | 917 | 926 | 0.638 | 0.665 | 729 / 3 |

Размер составного индекса — **760 kB**, частичного — **128 kB**. Первый селективный запрос и частичный запрос различаются предикатом и числом строк; их время нельзя считать сравнением двух индексов на одной нагрузке. Для обязательного до/после используется один и тот же score=1 запрос.

У селективного запроса уменьшилось число прочитанных страниц таблицы, появился Bitmap Heap Scan с Bitmap Index Scan. При score≥1 требуется вся таблица (99224 строки), поэтому выбран Seq Scan даже при наличии индекса. Тестовые индексы удалены в конце; PK-индекс сохранён. Исходные таблицы не менялись.

Замер 12.10.2026 на загруженных локальных CSV в отдельном PostgreSQL 17, без параллельных workers (`max_parallel_workers_per_gather=0`) из-за лимита shared memory контейнера. Страницы преимущественно прогреты предыдущими работами; shared hit означает попадание в буфер, а shared read — чтение в буфер, не обязательно с физического диска. Время зависит от оборудования и кэша. Полные планы — plans.json, консольный вывод — results.txt.

## Контрольные вопросы

1. Индекс невыгоден при низкой селективности, дорогих обращениях к heap, маленькой таблице или несовпадении предиката/выражения.
2. Равенства по ведущим столбцам и затем диапазон ограничивают непрерывный участок B-tree; обратный порядок обычно сканирует больше ключей.
3. Частичный индекс полезен для частого запроса на небольшое устойчивое подмножество, если условие запроса логически включает предикат индекса.

## Запуск и состав

Подключение: `psql -h localhost -p 5433 -U student -d olist`. Схема olist должна быть загружена по №1. Запуск из этой папки: `psql -h localhost -p 5433 -U student -d olist -v ON_ERROR_STOP=1 -f lab13.sql`. Каждый файл запускайте в отдельном сеансе: временные таблицы принадлежат сеансу. ФИО и группу впишите в шапку SQL. `results.txt` содержит фактический вывод на ваших CSV.
