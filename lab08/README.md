# lab08. ER-модель купонов

Вариант 4. Три новые таблицы — coupons, coupon_categories, coupon_uses. Диаграмма `erDiagram.png` показывает ключи, связи и обязательность; `schema.dbml` можно открыть в dbdiagram.io. Исходные объекты Olist не копируются.

## Бизнес-правила

| Правило | Реализация |
|---|---|
| Купон имеет уникальный код | uq_coupons_code, NOT NULL |
| Купон выпускает один существующий продавец | fk_coupons_seller, NOT NULL |
| Интервал действия непустой, начало включено, конец исключён | ck_coupons_dates; границы использования проверяются запросом |
| Процент скидки от 0 до 100, исключая 0 | ck_coupons_discount |
| Лимит использований — положительное целое | ck_coupons_limit |
| Категория купона существует в словаре Olist | fk_categories_olist |
| Пара купон–категория не повторяется | pk_coupon_categories |
| Использование относится к существующим купону и заказу | fk_uses_coupon, fk_uses_order, NOT NULL |
| Один купон применяется к одному заказу не более раза | uq_coupon_uses_order |
| Категория использования входит в применимость купона, сумма скидки положительна | составной fk_uses_category, ck_uses_amount |

Участие дочерних строк обязательное: у использования ровно один купон, один заказ и одна применимая категория. У купона, продавца, заказа или категории может быть 0..N связанных строк. Категории и купоны образуют M:N через coupon_categories. Издатель купона — информационная связь; купон допускается применять к товарам других продавцов.

В каждой новой таблице **5 строк**. Реальные order_id, seller_id и категории выбираются из доставленных заказов; use_date находится внутри интервала, скидка равна 10% цены выбранной позиции. Каталожные ограничения выведены из information_schema. Четыре ошибочные команды оставлены в комментариях с именем отклоняющего ограничения.

Общий лимит использований, наличие категории среди позиций заказа и срок использования — межстрочные правила. В этой DDL они проверяются диагностическими запросами (оба результата пусты на тестовых данных), а не CHECK. Для конкурентного применения необходима транзакция с блокировкой строки coupons и проверками перед INSERT; положительный usage_limit сам по себе не ограничивает COUNT использований.

## Контрольные вопросы

1. M:N требует промежуточной таблицы с внешними ключами к обеим сущностям и уникальностью пары.
2. Код купона — естественный альтернативный ключ; coupon_id — искусственный ключ, удобный для ссылок.
3. Диапазоны, обязательность, уникальность и существование ссылок лучше выражать CHECK/NOT NULL/UNIQUE/FK. Межстрочные и конкурентные правила требуют отдельного механизма.

## Запуск и состав

Подключение: `psql -h localhost -p 5433 -U student -d olist`. Схема olist должна быть загружена по №1. Запуск из этой папки: `psql -h localhost -p 5433 -U student -d olist -v ON_ERROR_STOP=1 -f lab08.sql`. Каждый файл запускайте в отдельном сеансе: временные таблицы принадлежат сеансу. ФИО и группу впишите в шапку SQL. `results.txt` содержит фактический вывод на ваших CSV.
