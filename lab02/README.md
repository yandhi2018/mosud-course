# lab02. Множества и мультимножества в SQL

Вариант 4: штат X = BA, штат Y = PE.

Множество A — `product_id` товаров, купленных клиентами штата BA
(заказы со статусом `delivered`). Множество B — то же для штата PE.

## Мощности множеств

| Величина | Значение |
|---|---|
| \|A\| (count DISTINCT) | 2569 |
| \|B\| (count DISTINCT) | 1318 |
| \|A ∪ B\| (UNION) | 3531 |
| \|A ∪ B\| (UNION ALL) | 3887 |
| \|A ∩ B\| (INTERSECT) | 356 |
| \|A − B\| (EXCEPT) | 2213 |
| \|B − A\| (EXCEPT) | 962 |

Проверка: 3887 (UNION ALL) − 3531 (UNION) = 356 = \|A ∩ B\| — совпадает,
как и должно быть по определению этих операций.

Мультимножество против множества (п.1): в A `count(*)` = 3683 строк, но
`count(DISTINCT product_id)` = 2569; в B — 1746 против 1318. Разница —
это дубликаты: один товар покупали в штате несколько раз.

## Выводы

- `UNION ALL` даёт больше строк, чем `UNION`, ровно на |A ∩ B|: общие
  `product_id` в `UNION ALL` посчитаны дважды (по разу из A и из B), а
  `UNION` схлопывает их в одну строку.
- Объединение и пересечение коммутативны: `A ∪ B = B ∪ A` и
  `A ∩ B = B ∩ A` — проверено симметричной разностью `(A∪B) EXCEPT (B∪A)`,
  которая возвращает 0 строк (см. п. 5 lab02.sql).
- Разность некоммутативна: `A − B ≠ B − A` в общем случае, если A и B не
  совпадают полностью — мощности `|A−B|` и `|B−A|`, как правило, различны
  (см. п. 6 lab02.sql).
- Обычный `SELECT` без `DISTINCT` — мультимножество: один и тот же
  `product_id` повторяется столько раз, сколько раз товар встретился в
  позициях заказов (п. 8). `UNION`, `INTERSECT`, `EXCEPT` без `ALL`
  возвращают множество (дубликаты удалены); их варианты с `ALL` —
  мультимножество.
