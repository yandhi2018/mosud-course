# lab07. NULL и качество данных

Эксперименты охватывают все неключевые столбцы orders, products и order_reviews. Для подсчёта SQL NULL строки переводятся в JSONB: пропуск получает значение JSON null. Пустые строки отдельно учитываются только в профиле текста отзывов.

`COUNT(*)` заказов — **99441**, `COUNT(order_delivered_customer_date)` — **96476**, разница **2965**. Оба ошибочных сравнения `= NULL` и `<> NULL` дали 0 строк; правильные IS NULL и IS NOT NULL — 2965 и 96476.

| Эксперимент | Результат |
|---|---:|
| NOT IN с существующим id и NULL справа | 0 заказов |
| NOT EXISTS с теми же id | 99440 заказов |
| Фильтр review_score ≥ 4 в ON | 99441 уникальный заказ, 99791 строка |
| Фильтр review_score ≥ 4 в WHERE | 76120 уникальных заказов, 76470 строк |

Фильтр в ON оставляет все заказы; отсутствие подходящего отзыва создаёт NULL справа. WHERE отбрасывает эти строки, поскольку `NULL >= 4` — UNKNOWN. Число строк JOIN отличается от числа заказов из-за нескольких отзывов.

| Показатель | Пропусков | Доля |
|---|---:|---:|
| Заказы без фактической даты доставки | 2965 | 2.98% |
| Товары без категории | 610 | 1.85% |
| Отзывы без текста | 58247 | 58.70% |

Отсутствие текста отзыва естественно: оценку можно оставить без комментария. Дата доставки отсутствует у незавершённого заказа закономерно; **8 delivered-заказов без даты** требуют проверки качества. COALESCE подставляет текст, NULLIF превращает нулевой знаменатель в NULL и предотвращает ошибку деления.

## Контрольные вопросы

1. NULL представляет неизвестное значение; равенство двух неизвестных нельзя считать истинным, поэтому получается UNKNOWN.
2. WHERE сохраняет только TRUE и может удалить строки, дополненные NULL внешним соединением.
3. NOT EXISTS проверяет наличие совпавшей строки; NULL в подзапросе не совпадает по равенству и не отравляет предикат целиком.

## Запуск и состав

Подключение: `psql -h localhost -p 5433 -U student -d olist`. Схема olist должна быть загружена по №1. Запуск из этой папки: `psql -h localhost -p 5433 -U student -d olist -v ON_ERROR_STOP=1 -f lab07.sql`. Каждый файл запускайте в отдельном сеансе: временные таблицы принадлежат сеансу. ФИО и группу впишите в шапку SQL. `results.txt` содержит фактический вывод на ваших CSV.
