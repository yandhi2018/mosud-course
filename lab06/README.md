# lab06. Подзапросы и логика предикатов

Вариант 4: покупатели, число заказов которых выше среднего для их штата. Покупатель определяется `customer_unique_id`, группа сравнения — `customer_state`; число заказов считается для пары этих атрибутов по всем статусам. Это позволяет учитывать повторные покупки, поскольку `customer_id` в Olist обычно соответствует одному заказу.

`customer_counts` материализует число заказов, `state_means` — среднее каждого штата. Основное решение использует коррелированный скалярный подзапрос и EXISTS. Альтернатива вычисляет среднее в CTE и соединяет его с покупателями. EXISTS показывает наличие покупателя с меньшим числом заказов; при превышении среднего это дополнительное условие уже следует из основного.

Обе формы нашли **2962 пары покупатель–штат**, EXCEPT в обе стороны — 0. В SP — 1296, RJ — 421, MG — 338, PR — 145. Максимум — 17 заказов у покупателя `8d50f5eadf50201ccdcedfb9e2ac8455` в SP.

`> ANY` означает превышение хотя бы одного значения в штате, `>= ALL` — достижение максимума. Для демонстрации числа заказов предварительно дедуплицированы: кратность одинаковых значений не влияет на ANY/ALL и уменьшает повторную работу. NULL штата обрабатывается в основных решениях через IS NOT DISTINCT FROM; в исходных данных штаты известны.

## Контрольные вопросы

1. Коррелированный подзапрос ссылается на атрибут текущей внешней строки; независимый можно вычислить без неё.
2. EXISTS удобен при проверке самого факта связи; не требуется получать значения или удалять дубликаты. NOT EXISTS также устойчив к NULL справа.
3. Скалярное выражение допускает одно значение: несколько строк приводят к ошибке, отсутствие строки даёт NULL. Здесь GROUP BY гарантирует одну строку среднего на штат.

## Запуск и состав

Подключение: `psql -h localhost -p 5433 -U student -d olist`. Схема olist должна быть загружена по №1. Запуск из этой папки: `psql -h localhost -p 5433 -U student -d olist -v ON_ERROR_STOP=1 -f lab06.sql`. Каждый файл запускайте в отдельном сеансе: временные таблицы принадлежат сеансу. ФИО и группу впишите в шапку SQL. `results.txt` содержит фактический вывод на ваших CSV.
